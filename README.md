# FourQuadrants GPUI

原 FourQuadrants 的 macOS 原生重构。Rust + GPUI 负责主界面和业务，Swift/AppKit 负责 RTFD 富文本、图片、SwiftData 迁移、Foundation 剪贴板解析与本地通知。仅面向 macOS 14+；当前在 Apple Silicon / macOS 27 上构建与验证。

## 安装

从 [GitHub Releases](https://github.com/cod7ce/FourQuadrants-GPUI/releases/latest) 下载 `FourQuadrants-GPUI-0.19.1-arm64.zip`，解压后将应用移入“应用程序”。当前发布包支持 Apple Silicon、macOS 14 及以上。包使用 ad-hoc 代码签名，尚未经过 Apple 公证；macOS 可能阻止首次打开，可在核对来源后通过“系统设置 → 隐私与安全性”允许打开。

## 启动

需要 Rust 1.89+、Xcode 与命令行工具。依赖锁定在 `Cargo.lock`，GPUI 0.2.2 + gpui-component 0.5.1。启用 `runtime_shaders`，不需要另下载 Metal Toolchain。

```sh
bash scripts/build-native.sh
cargo run --locked
```

打包为可双击的应用：

```sh
bash scripts/bundle.sh
open "dist/FourQuadrants GPUI.app"
```

优化构建用 `bash scripts/bundle.sh release`。包采用 ad-hoc 签名，尚未做 Developer ID 签名或公证。构建脚本保留原生通知 helper 的独立 bundle，并从官方地址下载和校验固定版本的 Sparkle 框架。

使用演示数据（不会调度或清理真实提醒）：

```sh
mkdir -p target/demo
cp fixtures/demo.json target/demo/data.json
cargo run --locked -- --data target/demo/data.json
```

演示数据的周固定为 2026-10-12。正常启动不会预填示例任务。

## 功能

- 四象限、周议程、42 格月历、当日任务、跨周收集箱、按周筛选的标签页和任务搜索。四象限按内容区实际宽度自适应：840px 及以上显示 2×2，更窄时按“紧急且重要、紧急不重要、重要不紧急、不紧急不重要”纵向排列，卡片随内容增高、整页滚动；侧栏自动计入可用宽度，任务编辑使用独立窗口。
- 四象限周选择器右侧显示“完成进度”、强调色进度条和紧凑的“已完成/总数”，元素间距为 6px；按字体与文字实际宽度预留空间，进度条由 140px 逐渐缩短，剩余宽度不足 40px 时才隐藏，只保留文字与数量；各象限标题同步显示对应完成数。统计只计入所选周的顶层任务，不受搜索或隐藏已完成影响。底部收集箱任务使用无底色的细边框卡片，统一预留两行文字高度，长标题最多显示两行；悬停时背景轻微高亮，支持 Shift＋单击切换关注、双击编辑和拖拽安排。
- 月历使用周一开始的 6×7 连续网格，顶部切换月份与返回今天；今天用强调色圆圈标记，选中日期显示细边框，周末略微着色。格内以象限颜色圆点表示任务，拥挤时显示剩余数量；下方保留颜色图例。选中日期的完整任务在侧边按待办、已完成分组，保留彩色标签、换行、打开编辑与拖拽排期；内容宽度不足 720px 时改成上下布局并整页滚动。
- 周议程在逾期区域下方、每日卡片上方显示“未规划”任务框，列出本周未设置截止日期的任务；每日卡片顶部横向显示日期与星期，任务在下方使用完整宽度。侧栏保留总览、周议程、日历和笔记入口，不展示快捷键文字，原快捷键继续有效；收集箱仅保留底部卡片区，不再提供独立页面；四象限、周议程、日历、笔记及工具栏导出图标沿用原版自定义绘制，分别为等大圆角四格、带周横条的日历、带日期点的日历、三行笔记和向上分享箭头，保持原版 24×24 坐标与 1.8 描边，颜色跟随主题；标签仍可查看对应任务。
- 任务标题、工单、备注、多个链接、截止时间、提醒、完成时间、标签、进展记录。双击查看任务与新建统一打开独立任务窗口，默认 960×760，左右两栏固定展示：左侧为标题、备注、链接和进展，右侧为工单、所属周、截止时间、提醒、象限、标签和子任务；长文本、历史记录与子任务仅在各自区域内滚动。日期使用日历选择，时间使用小时、分钟数字面板选择（分钟按 5 分钟递增），无需手填格式；提供“今天”（当天 18:30）、“明天”（次日 18:30）、“本周”（当周五 18:30）和“清空”快捷操作。底部显示未保存或已保存状态；主窗口宽度能容纳时居中于主窗口，否则居中于主窗口所在屏幕的可用区域，并避开菜单栏和 Dock。弹窗与主窗口共享主题、字体、色彩、透明度、Blur 和背景图，设置即时同步；不显示原生红黄绿按钮及完成对勾，右上角关闭，底部右侧依次为“删除”“保存”；进展记录与子任务的删除操作使用垃圾桶图标，仅悬停对应行时显示并保留原布局空间。重复打开或切换任务复用弹窗，关闭、切换与失焦前保存，验证或写入失败时保留草稿；主页面拖动排期后，弹窗同步未编辑字段。
- 最多三级子任务；任务行默认无背景，悬停时高亮；仅 Shift＋单击以半透明强调色背景标记当前关注的任务，再次 Shift＋单击取消该项，其他关注项保持不变；普通单击不改变任何关注标记，双击只打开任务弹窗，也保留原有标记。关注标记在当前应用会话内跨页面保留，关闭任务弹窗不会清除，重启后重置；复选框、展开箭头、拖拽与 Option＋单击链接保持独立操作。树形任务行之间保留 3px 间隔，父子同时选中时色块彼此分开；以淡色 L 形分支线连续显示层级，子任务复选框左边缘对齐父任务标题（含标签）起点，连线与复选框留出 6px 空隙，横线对齐复选框中心，末项连线在首行收尾，长标题换行与字号调整保持对齐，右侧的完成数量与箭头可展开/收起子任务。总览与标签页的树形任务列表将彩色标签文字放在标题前，不加圆点或 `#`，长标题自动换行；工单、截止时间和提醒使用下方的小字号信息行，最新进展显示为单行摘要。四象限顶层任务、每日议程和标签列表中的已完成任务统一放到待办下方的“已完成 N”分组，隐藏已完成时连同分组标题一起隐藏；收集箱卡片高度随字号同步调整。拖拽换象限、排序、排期，拖动时显示浮动任务预览、排序插入线和目标区域高亮；详情中可添加子任务、返回父任务或提升为顶层。
- 对历史未完成任务逐项选择结转；保留原版的移动、复制父项并移动未完成子项、标记完成三种规则。
- 笔记按周独立保存，直接在页面内编辑 Markdown，提供“编辑 / 对照 / 预览”三种视图；宽窗口默认源文与实时预览并排，窄窗口切换编辑或预览。模式切换、保存状态和失败重试与周选择器共用一行，正文区不再重复显示“笔记”标题。支持标题、粗体、斜体、列表、待办、引用、链接、代码与表格；格式工具栏可对选中文字操作。图片通过“图片”按钮、粘贴或拖入添加，在预览中随正文显示，无需打开富文本弹窗。输入时自动保存；失败保留文字和图片草稿，显示“未保存”和重试入口。每周的输入撤销历史独立，删除图片标记后保存时回收该图片，当前编辑内仍可撤销恢复。任务正文的富文本与附件仍可通过原生编辑器编辑，保留手动保存与关闭确认。
- 启动/激活时识别剪贴板工单，确认象限后创建；自定义规则、捕获组、自动标签和 Foundation 实时预览。
- 跟随系统、深色、浅色三种模式；独立强调色色板，预设色后提供 MonoCode 式“自定义”入口：连续饱和度/亮度色板、色相条和 HEX 输入，拖动或输入有效的六位色值即保存并生效，支持方向键微调；无效输入不覆盖已保存颜色，预设色、重置与撤销保持同步。界面色相、饱和度与深色亮度（默认 5%，可调至 0%），支持即时预览与重置色彩。窗口透明度（0–100%）与窗口 Blur（0–64px）独立调整，0% 透明度为实色，Blur 为 0 时清晰透视；字体与字号；背景图片、图片模糊、暗化、填充方式。所有数值设置使用滑块，显示当前值并支持方向键微调。旧海洋、森林、终端主题仍可读取，首次调整色彩时转换为对应参数。
- 参考 [MonoCode](https://github.com/hardbeat920/monocode) 的中性灰界面、细分隔线和紧凑间距，统一线性图标、输入框与选中态；四象限保留低饱和语义色。深色主题使用更深的底色和较轻的卡片提亮；单行输入框与文字按钮至少 32px 高，随字号一起放大。设置页提供主题缩略预览与分类导航。
- 内容延伸至窗口顶部，无独立标题栏和底部状态栏；侧栏顶部保留原生红黄绿按钮，该处及工具栏标题/留白区域支持拖动窗口。标题栏默认高 40px，大字号时适度增高；图标侧栏模式下，标题栏分隔线贯穿窗口；标题栏右侧的任务操作按钮统一为 22px 点击区域；按图形留白补偿视觉尺寸，结转采用“任务列表＋右箭头”线性图标，与导出区分；隐藏已完成、结转、导出图标分别使用 16px、17px、18px 画布，新建图标仍为 13px：四象限和周议程显示隐藏已完成、结转、导出、新建；日历只显示新建；标签页只显示隐藏已完成与新建；笔记和设置不显示任务操作按钮；周标题及较小字号的日期区间独立保留在下方，选择器宽度固定，日期起止分别与周信息左右边缘对齐；当前周不显示状态标签，切到其他周时在周选择器右侧显示“返回图标＋本周”按钮，点击回到当前周。顶部不再常驻搜索框，⌘F 临时打开搜索行、Esc 清空并关闭；标题栏的强调色“＋”新建按钮与 ⌘N 使用相同创建流程，打开详情后可选择象限；在日历和周议程中自动安排日期，在标签页中自动带上当前标签。侧栏开关采用 MonoCode 同款 Hugeicons 面板图标，展开与收起共用图标；标题栏中为 14px 图形、24px 点击区域，收起后的图标栏中与导航统一为 18px 图形、32px 点击区域并居中对齐，悬停时轻微提亮；工具栏按钮或 ⌘B 可收起/展开侧栏，收起后保留 44px 图标栏，页面入口与标签支持悬停提示，设置固定在底部；图标栏顶部按钮可恢复完整侧栏。窗口最小尺寸为 520×560；宽度低于 760px 时保留图标导航，展开时显示侧栏抽屉；任务弹窗独立于主页面，不占用内容区。保存失败等错误在内容区显示可关闭的提示。
- 沿用原版 FourQuadrants 的应用图标，覆盖应用包、Dock 及通知助手；侧栏恢复原版红蓝／橙灰四格标志和“肆”名称（英文为 Four Quadrants）；中英文界面；JSON 完整导入/导出，按周 Markdown 分享，任务操作撤销/重做。
- 保存成功后更新状态；原子替换、上一份有效备份、文件锁及并发修改检测；损坏数据不自动覆盖。

任务日期与提醒通过日历及时间选择组件设置，按本地时间保存；截止也可只设置日期。不存在或有夏令时歧义的时间会报错并保留草稿。完成任务不自动完成其子任务，与原版一致。拖动整个任务树时统一更新所属周，修正原版部分操作留下父子周不一致的问题。

设置 → 外观使用“窗口透明度”和“窗口模糊 · Blur”两个滑块。透明度只改变窗口底色，文字与按钮保持不透明；侧栏与主区域使用相同效果。Blur 在原生窗口后方执行，0 表示清晰透明，调高数值逐渐模糊。可从透明度 40%、Blur 24px 开始调整；透明度 0% 为实色，仍会记住 Blur 值，方便再次调高透明度。背景图片的“模糊半径”只作用于图片，图片不透明度为 100% 时会遮住窗口后方内容。

已有 JSON 的 `glass` / `opacity` 仍按旧含义读取，首次调整窗口效果时才写入独立的 `windowEffects`，避免更新应用时改变原有外观。旧效果继续使用 `NSVisualEffectView`；新 Blur 通过运行时解析的 WindowServer 接口设置半径，无静态私有框架链接。这一接口不是公开 API，若系统不支持会显示错误。当前 macOS 已通过真实窗口 0 / 24 / 64px 的视觉对比。

## 数据与旧版迁移

新应用使用独立路径，不会直接修改旧版数据库：

```text
~/Library/Application Support/FourQuadrants GPUI/
  data.json          主数据
  data.json.bak      上一次成功保存前的有效版本
  data.json.lock     写入锁（请勿在程序运行时删除）
  Backgrounds/       复制的背景图与模糊缓存
  Recovery/          原生富文本保存副本
```

在设置中选择“导入旧版 SwiftData”，选择旧版 `.store` 文件。**先退出旧应用**，避免复制过程中旧数据库仍在写入。helper 会复制数据库、WAL/SHM 和 externalStorage 附件到临时目录，只在副本上运行 SwiftData。成功后保留任务 UUID、父子、标签、进展、所有日期、RTFD 和图片，合并到新数据。

也可单独运行迁移工具，查看或保留导出结果：

```sh
target/native/four-quadrants-helper export-store /path/to/FourQuadrants.store /path/to/backup.json
cargo run --locked -- --validate /path/to/backup.json
```

实际 `.store` 路径由旧版 SwiftData 配置决定，可能位于 Application Support 或旧沙盒容器；不要根据文件名猜测并移动原库。原库异常关系、重复周笔记或不支持的 schema 会报错，需要先检查导出内容。

JSON 导入是**合并**：保留本地设置；相同内容去重，ID 冲突保留为稳定新 ID，重复导入不重复新增。同周不同笔记进入冲突归档，可在该周笔记页面恢复。孤立进展记录保留在 JSON 的 `orphanProgressNotes`。任务的 Markdown 分享不包含笔记，也不能替代完整 JSON 备份。

笔记使用现有兼容版本的 [GPUI Component InputState](https://docs.rs/gpui-component/0.5.1/gpui_component/input/struct.InputState.html) 编辑源文，结合 Markdown AST 和原生组件实时预览。图片以原始字节内嵌在 JSON 中，支持 PNG、JPEG、WebP、GIF、BMP、TIFF，单张最多 20 MiB，每篇总计最多 50 MiB；随 JSON 导入导出一起携带，不依赖临时文件。外部图片网址不自动下载，需将图片插入笔记。旧富文本在后台转成 Markdown 和图片，打开页面本身不改数据；第一次编辑保存时保留原普通正文、RTFD 字节与归档版本，无法转换的附件保留下载入口。若普通正文与富文本不同，两份内容都会保留。

首次保存 Markdown 笔记时，主数据从 schema 1 提升到 schema 2；写入前仍保留完整 `.bak`，旧版程序会明确拒绝新 schema，避免误删新字段。应用版本从 0.19.0 开始管理，与数据 schema 独立。

旧版 UserDefaults 外观设置、自定义规则与背景图片不在 `.store` 中，目前需要在新设置页重新配置。JSON 备份中的背景图字段为本机文件路径；跨机器恢复时需同时带走背景文件或重新选择。

## 快捷键

| 快捷键 | 操作 |
|---|---|
| ⌘ N / ⌘ F | 新建任务 / 搜索 |
| ⌘ B | 收起 / 展开侧栏 |
| ⌘ 1 / 2 / 3 | 四象限 / 周议程 / 日历 |
| ⌘ / | 笔记 |
| ⌘ , | 设置 |
| ⌘ ← / → | 上一周、下一周（日历为月份） |
| ⌘ T | 今天 / 本周 |
| ⌘ + / − / 0 | 放大 / 缩小 / 恢复字号 |
| ⌘ E | 导出 Markdown |
| ⌘ ⇧ V | 从剪贴板创建任务 |
| ⌘ ⇧ H | 显示/隐藏已完成 |
| ⌘ Z / ⌘ ⇧ Z | 任务操作撤销/重做；输入框内为文字撤销 |
| ⌘ S | 保存任务弹窗 |
| ⌘ Enter / ⌘ W / Esc | 保存并关闭任务弹窗；主窗口 Esc 关闭搜索或浮层 |
| Option + 单击任务 | 按住时有链接的标题显示强调色与下划线，点击前保存编辑草稿并打开第一条链接；适用于任务列表、底部收集箱卡片及详情中的父子任务入口 |

富文本窗口内支持 ⌘ S 保存、原生文字编辑快捷键与撤销。

## 当前边界

这是可本地运行的重构版本。四象限和编辑流程重新设计为 GPUI 界面，细节并非旧 SwiftUI 界面的逐像素复制。系统通知实际送达、用户真实旧数据库迁移、中文输入法及全部多屏交互仍需要在真实使用中验收。

原版的 iCloud/CloudKit 配置没有迁移为同步服务；原版当前构建本身也未启用 CloudKit entitlement。

## 版本与更新

当前版本为 **0.19.1**，以 `Cargo.toml` 为准，应用包的两个版本字段必须同步。设置 → **版本** 显示当前版本，提供手动检查更新与发布记录入口。完整应用包内嵌固定版本的 **Sparkle 2.10.0**，更新源独立于旧 SwiftUI 应用；自动检查、后台下载与系统配置统计默认关闭。`cargo run` 不加载 Sparkle，`--data` 模式在加载框架前禁用全部更新操作。

安装前以及系统最终退出时，均使用现有退出检查保存任务与笔记，写入或校验失败时保留草稿并暂停更新；富文本窗口必须先保存并关闭。更新包使用 Ed25519 签名，打包脚本会核对应用内公钥；缺少公钥时拒绝生成发布包。签名私钥只保存在本机钥匙串或发布环境的秘密变量中，不进入仓库。构建与本地签名步骤见 [发布说明](docs/RELEASING.md)。

Sparkle 更新签名与 Apple Developer ID 签名是独立的。当前应用采用 ad-hoc 签名，尚未取得 Developer ID 分发签名或完成公证。独立更新源使用本仓库 GitHub Releases 中的 `appcast.xml`，与旧 SwiftUI 应用互不替换。首次发布后，完整的跨版本安装与重启仍需在后续版本验收。
